Create `frontend/components/Map.module.css` and replace inline `style={{ ... }}` objects in Map.tsx with CSS module classes.

**Scope**: Map.tsx has many inline styles. The component structure remains intact — this is purely a style delivery refactor.

**Patterns to convert** (preserve green/natural colors):
- Page container: `position: relative, height: 100dvh, width: 100%, overflow: hidden` → `.page`
- Map container: `height: 100%, width: 100%` → `.mapContainer`
- Sidebar glassmorphism (if Map.tsx has one): Convert to CSS class with green-tinted gradient instead of teal
- Popup content styles: Convert to `.popup` classes with green theme colors
- Chip/badge styles: Convert to `.chip` classes with green palette
- Stat cards: Convert to `.statCard` classes
- Buttons: Convert to `.buttonPrimary` and `.buttonSecondary`

**Dynamic values**: Some styles depend on runtime data (e.g., marker colors from `markerColors(kos.jenis_kos)`). These MUST remain inline styles since CSS modules cannot access runtime variables easily. Convert only STATIC style objects.

**Strategy**: 
1. Create Map.module.css with all static styles grouped by component section.
2. In Map.tsx, replace each `style={{ ... }}` with `className={styles.xxx}` if the style object is fully static.
3. For mixed static/dynamic objects, extract the static parts to CSS and keep dynamic inline.

**CSS module naming**: Use camelCase per convention (e.g., `.popupHeader`, `.statCard`, `.routeButton`).

After conversion, verify Map.tsx still compiles and the production map page (`/`) renders correctly with green theme.
